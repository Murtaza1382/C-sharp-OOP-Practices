1. What is OOP?

OOP stands for:

Object-Oriented Programming

It is a programming paradigm where we organize programs around objects.

Instead of thinking only:

"What functions should my program perform?"

OOP also asks:

"What things (objects) exist in my system, what data do they have, and what can they do?"

For example, in a banking system:

A BankAccount
A Customer
A Bank
A Transaction

Each of these can be represented as an object.

Why is it called "Object-Oriented"?

Let's break the name into two parts:

Object

An object represents a thing with:

State → data it has
Behavior → things it can do

For example:

Bank Account

State:

Account Number
Owner Name
Balance

Behavior:

Deposit money
Withdraw money
Transfer money
Display account information

So an object combines:

Data + Behavior

Oriented

"Oriented" means the programming style is organized around objects.

So:

Object-Oriented Programming = Programming organized around objects.

2. Why was OOP created?

Before OOP, many programs were primarily organized around:

Functions
Procedures
Data structures

For small programs, this works very well.

But as software became larger, developers faced problems:

❌ Data was separated from the functions manipulating it.

❌ Large programs became difficult to organize.

❌ Code became difficult to reuse.

❌ Changes in one part could affect many other parts.

❌ Modeling real-world systems was harder.

OOP introduced a way to group related things together:

BankAccount
│
├── Data
│   ├── ownerName
│   ├── accountNumber
│   └── balance
│
└── Behavior
    ├── Deposit()
    ├── Withdraw()
    └── DisplayInfo()

This makes programs easier to:

Organize
Maintain
Reuse
Extend
Model complex systems

4. Why is it called a "Class"?

This is an interesting and deeper question.

The word class existed long before programming.

In ordinary language, a class means:

A group or category of things that share common characteristics.

For example:

Class of Animals

Animals in this category may share certain characteristics.

Class of Cars

Cars may have:

Brand
Model
Color
Engine

Similarly, in programming:

Class: BankAccount

represents a category of objects that share common properties and behaviors.

For example:

BankAccount #1
Owner: Murtaza
Balance: $1,000

and:

BankAccount #2
Owner: Ali
Balance: $500

Both are different objects, but they belong to the same class:

BankAccount

Therefore, the word class is very meaningful:

A class defines the common characteristics and behavior shared by a group of objects.

3. Types of Constructors

The terminology can vary slightly between languages, but these are the most common types.

A constructor with no parameters.

public BankAccount()
{
    accountNumber = "UNKNOWN";
    ownerName = "Unknown";
    balance = 0;
}

Usage:

BankAccount account = new BankAccount();
2️⃣ Parameterized Constructor

A constructor that receives parameters.

public BankAccount(
    String accountNumber,
    String ownerName,
    double balance)

    this.ownerName = ownerName;
    this.balance = balance;

    new BankAccount("ACC-001", "Murtaza", 1000);
3️⃣ Copy Constructor

A constructor that creates a new object using another object.

    accountNumber = other.accountNumber;
    ownerName = other.ownerName;

    new BankAccount("ACC-001", "Murtaza", 1000);

    new BankAccount(account1);

4. Constructor Overloading

Constructor overloading means having multiple constructors in the same class with:

The same name (the class name)
Different parameters

Example:

public class BankAccount

Java decides which constructor to call based on the arguments.

9. Restrictions of Static Methods

This is very important.

Because a static method belongs to the class, it doesn't automatically know which object you mean.

Consider:

class BankAccount
{
    String ownerName;

    static void displayOwner()
    {
        System.out.println(ownerName); // ❌
    }
}

Why is this wrong?

Imagine:

Account 1 → Murtaza
Account 2 → Ali
Account 3 → Ahmad

The static method asks:

Which owner's name should I use? 🤔

There is no specific object.

Therefore:

Static methods cannot directly access instance variables

❌

static void test()
{
    System.out.println(ownerName);
}
Static methods cannot directly call instance methods

❌

static void test()
{
    deposit(100);
}

Because deposit() belongs to a specific object.

Static methods cannot use this

❌

static void test()
{
    System.out.println(this.ownerName);
}

this means:

"The current object."

But a static method has no current object.

12. this() — Constructor Chaining

In Java:

this()

means:

Call another constructor from the same class.

Let's look at this:

public class BankAccount
{
    String accountNumber;
    String ownerName;
    double balance;


    // Constructor 1
    public BankAccount()
    {
        this("UNKNOWN", "Unknown", 0);
    }


    // Constructor 2
    public BankAccount(String ownerName)
    {
        this("UNKNOWN", ownerName, 0);
    }


    // Constructor 3
    public BankAccount(
        String accountNumber,
        String ownerName,
        double balance)
    {
        this.accountNumber = accountNumber;
        this.ownerName = ownerName;
        this.balance = balance;
    }
}

Now:

BankAccount account1 =
    new BankAccount();

Calls:

Constructor 1
       ↓
this("UNKNOWN", "Unknown", 0)
       ↓
Constructor 3

Another:

BankAccount account2 =
    new BankAccount("Murtaza");

Calls:

Constructor 2
       ↓
this("UNKNOWN", "Murtaza", 0)
       ↓
Constructor 3
Why use this()?

Without this(), you might repeat code:

BankAccount()
{
    accountNumber = "UNKNOWN";
    ownerName = "Unknown";
    balance = 0;
}
BankAccount(String ownerName)
{
    accountNumber = "UNKNOWN";
    this.ownerName = ownerName;
    balance = 0;
}
BankAccount(String accountNumber,
            String ownerName,
            double balance)
{
    this.accountNumber = accountNumber;
    this.ownerName = ownerName;
    this.balance = balance;
}

This repeats initialization logic.

Instead:

Constructor 1 ──┐
                │
Constructor 2 ──┼──► Main Constructor
                │
Constructor 3 ──┘

This is called:

Constructor Chaining

Important Rule of this()

In Java:

this() must be the first statement inside a constructor.

Correct:

public BankAccount()
{
    this("UNKNOWN", "Unknown", 0);
}

Wrong:

public BankAccount()
{
    System.out.println("Creating account");

    this("UNKNOWN", "Unknown", 0); // ❌
}

Because this() must come first.
